# 阶段提示词使用说明

先填写文末 Q1 中的“启动约定”，再按以下八个阶段发送提示词。各阶段均继承已确认的项目边界；只授权当前阶段时，完成后交付结果，不自动进入后续阶段。若已授权完整流程，可在检查通过后继续，只有实质性越界决定需要等待选择。

下文列出的 Skill 是当前可用的执行入口，实际使用时应读取对应 `SKILL.md` 及其要求的参考资料。同名 Skill 选择一套入口，避免混用不同副本；只加载当前任务需要的技能。本文是提示词模板，不表示其中的建模、计算或独立验收已经执行。

所有阶段使用统一的“边界处理回执”：写清触发事实及证据、触及哪条已确认边界、继续执行的影响；提供2—3个确实可行的方案，逐项说明适用条件、收益、局限、时间或资源成本、需重做哪些验证；推荐一个方案并解释依据，指出什么条件下应选其他方案。不要虚构备选项，只有一个可行方案时如实说明。等待我选择后再执行依赖该选择的步骤，期间继续不受影响的工作；沉默不表示同意，已经确认的事项不反复询问。
# 启动边界
将下列约定放在题目审计提示词之前，填好方括号内容后使用：

```text
请按以下边界执行本项目，并把已确认约定记录到项目状态.md。

【项目范围】
题目和附件位置：[填写]
本次工作范围与停止位置：[填写]
交付物：[填写]
语言与运行环境：[填写]
截止时间与计算预算：[填写；未知时请先估计]
允许写入的目录：[填写]
联网、数据上传和付费权限：[填写]

【研究与数据】
1. 先审计题目和附件，明确每问的输入、输出、研究事件、样本单位和硬约束。
2. 区分题目事实、数据观察、参考资料、暂定假设与实际计算结果；未知内容标记待核实。
3. 原始数据只读，派生数据另存；清洗记录包含规则、理由和影响数量。
4. 研究事件、标签、关键业务假设和目标权衡的实质改变，先提出具体方案并等我确认。

【模型与验证】
5. Skill提供候选池；先排除不适用模型，再确定基准、候选及尝试顺序。
6. 模型必须适配样本结构、删失类型和约束，不能只按名称或综合打分选模型。
7. 比较前确定验证划分和主要指标；所有数据驱动处理和阈值选择在相应训练范围内进行。
8. 最小运行保留核心定义和约束；缩小规模后先检查可估计性与可行性。
9. 临时结果不得冒充正式结果；所有结论对应实际运行、推导或明确来源。
10. 接受无显著效应、改进无收益和方案不稳定等结果，不为了预定结论调整数据或指标。

【自主执行与回退】
11. 既定方案和预算内的读文件、编程、修错与实验可自主推进。
12. 每阶段检查产物和进入下一阶段的条件；发现问题回到对应环节修正。
13. 需要改变任务含义、放宽硬约束、增加费用或上传数据时，说明原因、具体方案和影响后等待确认。
14. 已确认事项写入项目状态；只有出现新证据或范围变化时才重新提出。
15. 阶段结束报告实际完成内容、证据文件、检验结果、未验证事项及下一步。
```

# 题目审计
将每个子问题拆成研究对象、输入、输出、约束、评价指标和与其他子问题的关系。例如“制定信贷策略”不仅是预测违约概率，还要确定是否贷款、贷款额度和利率，并检查总额度、上下限和风险目标。

```text
请完成题目审计，先读取项目状态.md和原题。

【Skill】
使用 math-modeling 的建模手；PDF题目按需使用 pdf，Word题目使用 DOCX工具，表格附件使用 Excel工具。此阶段只理解任务和核对材料，不提前执行求解或论文生成。

【执行内容与产物】
1. 逐问建立任务表：研究对象、观察单位、独立样本单位、研究事件、输入、输出、决策时点可用信息、硬约束和验收要求。
2. 每项关键要求对应原题页码、段落或附件字段；列出各问之间需要传递的结果。
3. 区分题目事实、数据观察、文献依据和暂定假设，列出缺失附件及含糊措辞。
4. 在题目分析报告.md中保存审计结果，在术语表格.md中统一事件、变量和单位，并更新项目状态。

不能为了匹配某模型改写题意，不能把参考论文采用的定义当作题目要求；不得补造字段、标签或业务约束。必要的只读提取可以执行，当前不编写正式求解代码。

【触及边界时】
“达标”可能指当次达标、首次达标或连续两次确认：分别说明输出含义、需要的观测和对时点决策的影响，依据原题文字推荐，等待我确认。
附件缺失：可比较“补齐后继续依赖部分”“先做其余子问题”“在明确假设下只做方法方案”。说明哪些结论因此无法计算。

【完成条件】
所有子问题都有可检查的交付要求；关键歧义已解决，或明确列为阻塞项。未解决的事件定义不能被带入正式模型。
```

# 数据审计
```text
请基于已确认题意审计全部数据，并形成可追溯的处理方案。

【Skill】
使用 Excel工具读取和核对工作簿；使用编程手进行必要的数据统计与可复现处理；需要探索性图表时使用 科研可视化工具。遇到缺失值或异常处理方法选择时，按需使用 shumo-dictionary 查询对应条目，不把字典建议直接当作本题处理结论。

【执行内容与产物】
1. 建立数据字典，记录文件、工作表、字段含义、单位、类型、样本量、时间范围和表间关联键。
2. 检查缺失、重复、异常、特殊编码、标签分布、测量次数及关联后的遗漏或重复扩张。
3. 对每项清洗列出原始数量、规则、理由、受影响数量与潜在偏差；已确认规则可执行，语义不明的记录先标记保留。
4. 输出审计表、必要的探索图、处理记录及派生数据位置；保存读取和处理过程，使结果能够复核。
5. 区分描述性全数据审计与模型拟合：需要学习的填补值、缩放参数和筛选阈值留到相应训练折内估计。

【执行边界】
原始数据只读；不因难预测而删除样本，不把缺失标签默认改成阴性，不将技术重复当作独立样本。不得让测试集信息参与模型预处理参数估计。

【触及边界时】
异常值性质不明：可比较“保留并标记、采用稳健处理”“有来源依据后剔除”“主分析保留、做排除后的敏感性对照”。根据业务意义和影响规模推荐。
重复记录身份不明：比较“保留记录但按对象分组”“确认同一测量后合并”；说明合并规则、信息损失及标签冲突处理。
关键字段缺失：比较经论证的插补、调整可用特征或补充数据；不可插补的真实结局不得编造。
按统一边界处理回执交由我选择，未确认前不执行有争议的删除或重标注。

【完成条件】
数据数量与来源能核对，处理规则可复现，样本单位明确，影响后续结论的数据问题已解决或明确阻塞。
```

# 确定验证方式

```text
请在比较模型前设计本题验证方案，并把它写入题目分析报告.md的验证章节。

【Skill】
使用建模手设计评价目标，按需使用 shumo-dictionary 核对检验的适用条件和禁忌点；需要验证划分可行性时由编程手统计各折对象数、时间范围和类别数。此时不以测试结果挑选模型。

【执行内容与产物】
1. 为每问明确评价对象和场景：关系解释、新对象预测、未来预测、概率估计或决策优化。
2. 设计符合对象依赖和时间顺序的数据划分，区分训练、调参与最终评价的用途。
3. 指定主要指标、辅助指标、有效基准及比较规则；区分统计显著、预测改善和业务收益，不设置无依据的统一达标线。
4. 列出必须检查的假设、具体操作、判断依据、不通过时的处理和不确定性报告方式。
5. 优化问题另列约束残差、求解状态、可行基准、最优性证据和决策稳定性检查；无标签任务不要强套分类交叉验证。
6. 将填补、特征选择、调参、校准、阈值选择、质量门控及记录聚合纳入完整验证流程，登记版本与随机种子。

【执行边界】
不为了增加每折样本量拆散同一对象；不使用未来信息；不因结果难看更换主要指标。模型的研究事件必须与验证标签一致。

【触及边界时】
分组五折导致部分折没有阳性：比较“减少折数”“可行的重复分组留出”“补充样本后再验证”。按独立对象数和阳性覆盖推荐，不能通过复制阳性记录制造独立信息。
既要预测未来又要预测新对象：提出分别评价两种场景或选定主要场景，说明两者回答的问题不同。
原测试集已用于选模型：比较“建立新的独立测试集”“在现有数据上重新做完整嵌套评价并披露探索历史”；说明外部证据仍有哪些不足。
按统一边界处理回执提出选择，确认后冻结评价口径。

【完成条件】
划分实际可行，指标对应题意，基准和选择规则明确，信息泄漏路径有具体防护；没有数据支持的验证不声称可完成。
```

# 让ai比较基准模型和候选模型
- 基准模型的特点:假设少,参数少,可解释性高,可作为随后的对比参照
## **候选模型从哪来**
1. 数据结构要求的模型：时序数据先检查趋势、季节性、长度与预测跨度，不能直接优先选LSTM；删失数据根据右删失、左删失或区间删失类型选择适配的生存分析方法。
2. 基准模型的不足:如线性回归残差有非线性,可以增加样条,
3. 题目的业务机制,如农业题的轮作,损耗和超产,这些结构决定候选模型

```text
请依据题目审计、数据审计和验证方案确定模型尝试顺序。

【Skill】
使用建模手组织模型方案，使用 shumo-dictionary 按任务类别读取相关条目，保留数据要求、关键假设、禁忌点和模型缺陷。需要来源支持时使用 双引擎论文搜索；确需获取全文时再使用 nature-downloader。记录真实检索来源，不把模型名称匹配当作适用性证明。

【执行内容与产物】
1. 先做硬性筛选：能否回答题目、处理依赖结构和删失、表达硬约束、在现有信息下估计。关键条件不满足的模型不能靠评分补偿。
2. 区分无学习参照和正式基准；正式基准应可解释且满足任务必要结构。最多查询1—3个相关候选，本轮默认仅推进一个基准与一个有明确理由的候选体系，其余列为备用。
3. 逐模型给出候选来源、尝试优先级、相对基准解决的问题、所需假设、计算成本、验证方式和退出条件。先称“拟采用方案”，实验完成前不称“最佳模型”。
4. 写出可实现的变量、单位、核心公式、目标函数、约束、参数来源与求解步骤；解释模型之间传递的量是否具有一致含义。
5. 更新题目分析报告.md、术语表格.md与项目状态；基准和候选按同一验证协议比较。

【执行边界】
不因模型复杂、流行或获奖论文使用过而优先；不把求解器与统计模型放在同一层比较；不通过忽略关键约束构造过弱基准。检索不授权付费、上传项目数据或绕过访问权限。

【触及边界时】
所有候选均不满足数据要求：比较“缩小可回答的问题”“补充数据”“采用明确的情景假设仅给条件结论”，说明哪些改变需要我的决定。
候选计算超预算：比较“保留结构并用精确等价变换”“使用可报告误差或界限的近似求解”“增加预算”。不能把放宽约束的上界当作可行方案。
需增加第三个模型体系：说明现有两者失败的证据、新增价值和成本，供我选择替换、扩展或暂缓。
按统一边界处理回执提供选择，不通过修改标签来迎合候选模型。

【完成条件】
主方案可实现，候选优先级有依据，参数和假设有来源或明确待确认，验证方案与模型相容。按 math-modeling 的要求完成建模终检M1；不可用的独立质检如实标记，不冒称通过。
```

```text
【触及边界时】
小样本无法估计模型或满足最小组人数：比较“恢复足够数据”“全量单次拟合并减少重复”“拆开做模块检查后再整体验证”。按成本和检查覆盖推荐。
求解失败：先自主检查实现错误、单位和已有备用设置；若仍需改变模型或约束，提交“等价改写”“改用适配求解器”“调整模型假设”的具体方案，说明是否改变原问题。

按统一边界处理回执处理，继续不受影响的检查。

【完成条件】
关键手算样例、实际数据接口和硬约束检查通过，未收敛与未覆盖项明确，正式配置可恢复。按 math-modeling 的要求完成P1质检后再进入完整实验；缺失独立验收如实报告。
```

# Q1:开始要定边界,要定怎样

需要。边界应在“题目审计”之前交给 AI，并在审计后根据实际数据补全。开始时你只需要确定任务范围、交付要求、时间和资源；模型、参数和检验方法可以由 AI 提出方案。关键是明确哪些属于可以自主处理的技术选择，哪些会改变研究问题、数据含义或结论，需要先确认。

## 1. 启动前由我填写的内容

| 项目 | 需要填写的内容 | 示例或说明 |
|---|---|---|
| 任务范围 | 本次处理哪些子问题、推进到哪一步 | 先完成题目审计和模型方案；或完成求解及论文 |
| 输入材料 | 题目、附件、参考资料的位置 | 原题和原始附件是任务依据，参考论文仅供参考 |
| 最终交付 | 需要哪些文件和格式 | Python代码、结果表、检验记录、Markdown报告等 |
| 运行条件 | 语言、已有环境、可用设备 | Python；优先使用已有环境 |
| 时间预算 | 截止时间、单次长任务的预算 | 明确可用于调参和重复实验的时间 |
| 文件权限 | 工作目录、允许修改的范围 | 原始附件只读，派生数据和结果写入项目目录 |
| 外部资源 | 是否允许联网、上传、付费服务 | 可检索公开资料；上传数据或付费须另行确认 |
| 人工确认点 | 哪些决定必须先问我 | 标签含义、研究事件、关键业务假设和目标权衡 |

不清楚的项目可以写“请先提出建议”。不需要在启动前自己选好所有模型，也不需要凭空设定准确率、组数或风险权重。

## 2. 必须固定的边界

### 题意与研究对象

每问明确研究对象、研究事件、输入、输出及决策发生时能够获得的信息。不能为了方便套模型，擅自更改标签、研究事件、预测时点、独立样本单位或题目约束。例如，“某周当次浓度达到4%”“首次达到4%”“连续两次观测达标”是不同事件，不能互相替换后继续沿用同一个结论。发现原定义不合理时应说明原因和影响，提出修订方案再确认。

### 数据处理与证据

保留原始数据，所有清洗可追溯。缺失、异常、负值、重复记录和测序失败先解释含义，再决定处理；不为提高指标删除困难样本。区分“题目给定”“实际数据观察”“文献依据”“暂定假设”和“实际运行结果”。模拟或手算样例单独标明，不能混入正式样本、实验指标或论文结论。不能把未报告某项检验写成已证明没有做，也不能把笔记中的转述直接当成论文原文证据。

### 模型选择

Skill 推荐只作为候选池。先检查模型能否处理研究目标、样本依赖、删失和硬约束，再比较解释性、计算成本与效果；不允许用综合评分抵消关键不适用条件。优先确定一个有效基准和少量有理由的候选，区分统计模型、优化模型、求解算法和验证方法。模型排序是实验前的尝试顺序，最终选择依据统一验证结果和任务目标。

简单模型也必须适配数据：时间结构不自动意味着使用LSTM；有区间删失不能直接套用普通右删失处理；存在整数和轮作约束的正式基准不能为了简单而省略约束。未获准新增的模型可以列为建议，先说明它解决了已观察到的什么问题。

### 验证与结论

比较模型前确定数据划分、主要指标和使用场景。按对象或时间划分时，保留对应依赖结构；填补、标准化、特征筛选、调参、概率校准和阈值选择只使用相应训练数据。若聚合记录、质量门控或复检规则参与最终决策，也应作为完整流程一起验证。测试数据不能反复用于选择模型；确需修改评价方案时记录原因，并重新安排独立评估。

不预先要求必须得到显著结果、某个分组数或指定推荐时点。复杂模型没有改善、最佳方案是不分组、结果对假设敏感，都应如实报告。统计显著性、预测能力和决策收益分别评价；数值输出精度不等于统计可信精度。

### 最小运行与正式实验

最小运行用于检查逻辑和实现。可以减少重复次数、搜索组合或采用结构完整的子集，但必须保留事件定义、处理规则和需要检验的约束。缩小后应先检查样本是否足以估计参数、是否包含必要类别或删失类型、优化问题是否仍有可行解。

此前对话中“10名孕妇、分2组”的例子不能直接作为正式流程测试：如果正式约束为每组至少30人，该数据规模不能验证正式分组问题，不能为让它跑通而偷偷降低最小人数。上方示例已改为分别用人工样例检查区间构造和状态转移，再用足够规模的数据检查完整流程。若正式数据本来就小、单次拟合很快，直接使用全量数据，只减少Bootstrap或调参次数即可。

小规模结果不用于选择最终模型或写正式结论；正式实验恢复所需数据规模、搜索精度和重复次数，并检查收敛和不确定性。试验阶段的结果若已满足正式协议且可复现，可以保留，不必只因叫“试验版”就全部重算。

## 3. AI可以自主处理什么，什么时候需要停下来

| 情况 | 执行规则 |
|---|---|
| 读取附件、统计缺失率、核对单位、整理审计表 | 自主完成并报告发现 |
| 在既定方案内组织代码、修复实现错误、补充检查 | 自主完成，记录影响并重跑相关检查 |
| 在预先约定的候选和预算内调参、运行实验 | 自主完成，不必每次询问 |
| 普通求解失败或模型表现不好 | 先检查数据和实现，尝试既定备用方案；不能伪造成功或直接修改研究目标 |
| 更换研究事件、标签解释、关键业务假设、主要评价口径 | 说明原方案问题、备选方案及影响，等待确认后执行依赖部分 |
| 删除无法确定性质的样本、放宽硬约束、改变关键风险权重 | 先提出具体处理方案和影响，不能暗中修改 |
| 需超出计算预算、上传数据、付费或覆盖已有重要成果 | 先说明具体动作和原因，取得授权 |
| 信息缺失但仍有独立工作可做 | 标记缺口，继续不依赖该信息的工作 |

“需要确认”针对会改变任务含义或超出授权的决定，不应变成每一步操作都等待人工批准。已经确认的选择写入项目状态，后续沿用；有新证据需要修改时再提出。
